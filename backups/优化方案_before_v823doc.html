二、详细方案与开发原则

1. 远程接管与遥控（监控中心）已冻结

  • 入口：监控中心 3D 视口选中具身 → 右侧「具身信息」面板 →「远程接管」按钮（仅管理员角色可见）。
  • 形态：全屏弹窗，标题栏为平台统一样式「远程接管 · {具身名称}」；正文 iframe 内嵌狗原生控制台（当前测试地址 http://123.57.179.149:8188/）。
  • 连接控制地址在接入中心「基础信息」按具身配置（新建向导同步采集，新建 / 查看 / 编辑三态字段统一）；未配置时接管按钮置灰并提示。
  • 失败处理：iframe 5 秒加载不出来，仅提示「控制台加载失败」（不切换任何示意图、不提供降级页）。
  • 接管联动：接管即自动暂停当前任务，执行记录写入「人工接管」节点。
  • 结束接管：弹确认框，两个动作按钮——「恢复原任务」「回到充电桩 / 待命区」；右上角 ✕ 为关闭确认框（即取消结束、继续接管），✕ 无白底。
开发原则：① 平台不自绘遥控 UI，一期统一走狗原生控制台 iframe，控制台地址做成按具身可配置项；② 接管 / 结束接管都必须落执行记录，保证任务审计链完整；③ 结束接管的默认去向是「回到充电桩 / 待命区」，对应点位取自空间管理「充电/待命」用途点位。

2. 网络模式管理（监控中心 · 具身信息内）已冻结

  • 逐具身切换 在线 / 离线；弱网本期置灰，点击提示「开发中」。
  • 离线具身：地图标记「最后已知位置 + 离线时长」（平台侧以最后上报坐标 + 时间戳判定）。
  • 离线任务包列表：任务名 / 点位数 / 是否完整接收，未完整标「待补传」；媒体回传显示「已回传 x/y · 断点待续传」，恢复网络自动续传。
  • 已取货断网处置（离线面板独立区块，文案完整友好）：默认唯一策略「自动回充电桩等待重连」（已取货状态不允许原地等待）+ 重连倒计时；小程序订单同步显示「配送异常-处理中」。
开发原则：① 网络模式是逐机属性，切换入口统一收在具身信息面板，不做全局开关；② 断网期间的一切数据（点云 / 图像 / 日志）按「断点续传」设计，有网即回传，不丢不重；③ 载货断网属于配送异常链路，平台侧处置与小程序订单状态必须同源同步。

3. 小舆交互优化（全局 AI 助手）已冻结

  • 多轮对话 + 上下文记忆：会话时间线留存可上翻；支持上下文追问（「去 3F 巡检」→「改成 4F」）；历史会话可切换 / 新建。
  • 去固定快捷按钮：新会话开场小舆主动发欢迎语 +「可以这样说」示例气泡（按具身岗位能力集与绑定场景过滤）；输入框上方一行可横滑快捷胶囊：下任务 / 空间状态 / 狗子状态 / 异常复核，点即填入输入框。
  • 「下任务」不跳页：点击后改为对话区内 NL 引导文案（同新会话引导），引导用户用自然语言下任务。
  • 面板形态：可拖拽移动、可吸附右边缘展开为侧栏；Pad 端同一页面响应式。无「小舆.xiaoyu」名字标签。
  • 样式统一：深底卡片 + 细滚动条；用户气泡 / 小舆气泡 / 任务卡片 / 解析卡片 / 告警卡片统一圆角 + 边框 + 状态色；语音态（拾音中 / 识别中 / 执行中）输入框内动画 + 识别文字实时回显。
  • 主动提醒：异常告警（待复核 / 任务失败 / 电量低 / 越界）以小舆新消息进会话，消息内按钮直达处置页，形成沟通留痕。
开发原则：① 小舆是「有上下文的对话式助手」，不是一次性指令框——所有交互留痕、可追问、可回溯；② 快捷入口只做「引导填词」，真正的任务下达走 NL 解析链路（见第 5 节），不做硬编码按钮跳页；③ 告警进会话 = 通知中心 + 处置入口二合一。

4. 空间数据采集任务（任务中心）已冻结

  • 新业务类型「空间数据采集」：新建只需选 单体 + 楼层；支持一次选多层；不支持跨建筑（选第二栋楼拦截提示）。
  • 不设扫描方式 / 点云密度 / 完成后动作等参数；仅人工触发（任务类型锁定「人为触发」，无周期 / 定时选项）。
  • 执行即接管：保存下发 → 狗启动前往目标楼层 → 界面自动跳转「远程接管」→ 人控制狗完成扫图（狗语音播报「开始扫描 XF / XF 扫描完成」）。
  • 点云回传归属：按任务执行楼层归档（多层任务每层一个文件）；文件带信息记录（所属单体-楼层 / 采集时间 / 文件大小 / 采集任务名 / 采集人），空间信息面板与媒体归档可查。
  • 状态标签：「已对齐落图 / 待比对」；与既有模型比对本期只做「待比对」标记。
开发原则：① 扫图是「人控任务」：平台负责任务下发、跳转移交、数据回收，扫描过程本身交给远程接管；② 点云文件必须以「单体-楼层」为第一归属键，支撑后续按层比对与落图；③ 跨建筑拦截在前端与调度层双校验。

5. NL 任务自动解析（任务中心 + 小舆）已冻结

  • 先推理、再补填：AI 先推理完整任务要素；推理不出时以解析卡高亮缺项补填为主、小舆对话追问为辅。
  • 解析确认卡：任务类型 / 目标位置（可点开空间地图改选）/ 点位要求 / 返回结果要求 / 路径规则 →「确认并规划路径」/「重新描述」。
  • 路径规划弹窗显示路径子模型：不加载全量模型，只显示空间（房间盒）+ 重点系统 / 设备 + 重点位置的轻量化子模型，体现子模型提取能力。
  • NL 生成固定任务：识别出周期 / 时间字段，确认后创建固定任务。
  • 语音下达的一次性任务仅在小舆会话内跟踪；不做任何分期类标识（不对用户暴露开发分期）。
  • 入口统一：小舆输入、任务设置页「🎙 语音/文字建任务」按钮共用解析卡组件。
开发原则：① 解析链路 = 语义解析 → 岗位 / 能力校验 → 模板命中 → 确认卡 → 路径规划 → 下发，任何一步缺要素都在卡片内闭环，不阻塞对话；② 路径预计算只用子模型，是性能与「空间语义理解」展示的双重要求；③ 解析卡是公共组件，小舆与任务中心两处复用。

6. 接入向导扩展：充电桩 / 待命区 / 电量策略（接入中心）已冻结

  • 向导「充电与待命」环节：充电桩位置、待命区域（选空间管理「充电/待命」用途点位）；电量双阈值：回充阈值（默认 20%）、禁派阈值（默认 35%，需实测校准）。
  • 充电桩连接测试：向导与基础信息编辑均有「测试连接」，未测通拦截保存 / 注册（可跳过，稍后在基础信息再配）；查看态显示「已对接 ✓」徽标。
  • 基础信息页同步可查看 / 编辑充电与待命配置。
  • 连接控制地址：「新建设备」步骤连接参数下新增输入（远程接管控制台 URL，示例 http://123.57.179.149:8188/）；值随注册写入设备档案，基础信息可补录 / 修改；未配置时监控中心「远程接管」置灰。
  • 充电桩状态本期实现：监控中心地图充电桩标记三态（空闲 / 占用·显示具身名 / 故障）。
  • 低电联动：电量条双刻度线；低于禁派阈值具身标黄「暂停派单」；任务下发时电量不足拦截提示。
开发原则：① 充电桩 / 待命区是「点位」，统一引用空间管理点位库（用途 = 充电/待命），不另建坐标体系；② 连接测试是保存前置校验但允许跳过，兼顾联调期与演示期；③ 电量策略（回充 / 禁派）作用于调度层，所有派单入口统一过电量闸门。

7. 本体与模组接入（接入中心）已冻结

  • 模组清单写死 6 项：MID360 激光雷达 / 5G 数据模块 / 控制手簿电脑 / 扬声器拾音器模组 / 全景相机模块 / 空间智能模组。平台按清单写死对应功能页面。
  • 模组四态：已连接 / 异常 / 未连接 / 未搭载；异常可「重试连接」+ 连接日志弹窗（最近 10 条连接事件）；「一键重连全部」真实生效（异常 / 未连接 → 已连接，未搭载不参与）。
  • 模组异常反向置灰对应可执行任务开关并注明原因；5G 异常整机按离线处理。
  • 本体补：固件版本 / SDK 版本 / 最近心跳时间。
开发原则：① 模组状态是任务可调度的前置条件，状态 → 能力的映射在调度层统一判定；② 四态必须互斥且可解释（每个状态都有下一步动作：重试 / 查看日志 / 无）；③ 模组清单是硬编码白名单，新模组上线 = 平台发版。

8. 门控对接（空间管理 · 智能通行控制，龙岗 10/21）已冻结

  • 页面位置：空间管理 →「智能通行控制」页签（点位管理之后）。布局：左空间地图（单体 + 楼层双下拉联动，门 / 梯标记可点选）+ 右设置列表（约 5:7）。
  • 空间管理自动识别门 / 电梯：语义识别将 BIM 中门、电梯构件单独提取；空间组织模型区顶部「门 / 电梯」过滤开关，勾选即单独高亮；点击弹构件信息面板（门控 / 梯控配置 + 构件标签 + 列为关联设备，与通用构件能力一致）。
  • 门类型二元：自动门（配门控 API）/ 非自动门（视觉识别）；门状态：常开 / 常关。自动门未配 API → 红色显示（模型标记与门点列表同步红）。
  • 统一网关 + 单门覆盖：配置第一扇自动门时可勾选「统一网关」——勾选后所有自动门默认共用视为配好；每扇门可单独改 API（兼容商铺各自网关与整楼统一网关两种情况）。本期统一网关勾选灰显禁用（标注「暂不可改」，默认按已启用继承，后续版本放开）。
  • API 单源配置：空间组织构件信息面板中门控 API / 梯控 API 只读（灰化禁编辑），门下注明当前生效来源（继承统一网关 GW-01 / 未配置 ⚠）；配置与修改入口统一在「智能通行控制」。
  • 通行状态机：接近门 → 停下检测（视觉识别开 / 关）→ 已开通过 / 未开发开门请求 → 等待确认 → 超时重试 N 次（可配）→ 人工兜底（小舆推送 + 远程开门 / 改路线 / 终止）。
  • 门控页签：门点管理表（名称 / 所在空间 / 类型 / API / 通行策略 / 关联路线）+ 通行日志。
  • 监控中心地图门标记区分自动 / 非自动，通行中闪烁。
开发原则：① 门 / 梯是「空间构件」不是独立设备台账，识别、标注、配置都挂在空间模型上；② 门控 API 配置遵循「默认统一网关、单门可覆盖」的最小配置原则；③ 未配 API 的自动门是配置缺陷，必须在地图与列表双端红色显性暴露；④ 门 / 梯 API 单源维护——只在「智能通行控制」配置，空间组织侧只读，防止双写不一致。

9. 梯控对接（空间管理 · 智能通行控制，宁波 10/31）已冻结

乘梯指令集（9/28 定稿顺序）：

呼梯 → 到梯检测 → 进轿厢（不改位姿）→ 选层 → 切图目标层 → 轿厢内重定位（平台自动指定点位）→ 到达判定 → 开电梯门 → 出轿厢
  • 选层指令按「支持 API」设计，附降级说明：电梯不支持选层 API 时，由人工 / 机械按层，平台仅下发呼梯与到层检测。
  • 电梯状态二元：可乘（已接梯控）/ 不可乘（未接梯控，红标）；电梯通过空间名称「电梯 / 电梯间」语义识别。
  • 电梯构件信息面板：梯控状态 / 服务单体（只读 = 当前所在单体）/ 服务楼层（点击胶囊多选，保存为「B1、1F、3F」格式） / 梯控 API / 轿厢定位方式。
  • 梯控配置表：电梯名称 / 服务楼层 / 梯控 API / 轿厢内定位方式；每动作配下发指令、成功判定、超时重试。
  • 跨层任务在任务详情与地图上显示「乘梯中」节点；异常分支：呼梯无响应（重试 → 人工）、轿厢内断网（到站自动恢复定位）。
开发原则：① 指令链串行、每步有成功判定与超时重试，联调期可逐步排查；②「进轿厢不改位姿」是有意砍掉正对门位姿检测的简化决策，不要加回；③ 选层是必须保留的 API 能力项，降级只降「按层方式」，不降指令链结构。

11. 配送小程序（移动端 H5，单独设计）已冻结

入口：深圳龙岗公众号菜单 / 链接进入；需登录（微信手机号授权，首次进入登录页，记住账号后二次打开自动登录）；店员端本期不做。

  • 登录：微信一键登录 → 手机号授权弹窗（允许 / 拒绝）；「我的订单」页顶部账号条 + 退出登录；支持 ?logout=1 强制退出（演示用）。
  • P1 下单：顶部大语音按钮「语音下单」→ 语音解析自动填写下方表单，也可直接手动填；① 选商铺（DQ / 奈雪，与平台取货点同源）→ ② 订单号（仅文本核对，不接 POS）→ ③ 送达点（预设点列表 + 搜索，支持手动输入空间文字，经空间语义匹配平台地图，匹配不上提示「不在配送范围」）→ ④ 备注 = 送达提示语（如「小姐姐你的小饮料到了」，狗用作送达播报）；温馨提示「机器狗配送可能存在迷路等情况，希望多一点耐心 ❤」；提交后提示「当前排队第 N 位」+ 预计送达。
  • P2 配送进度：状态条 + 2D 小地图实时位置 + 预计送达 + 联系店员（显示店铺电话，平台取货点配置同源）。
  • P3 我的订单：时间倒序 + 状态标签 + 筛选；滞留订单在列表正常显示「滞留提醒」状态。
  • P4 订单详情：全过程时间线；滞留判断：狗长时间未移动，或长时间未送达且未在执行其他订单 → 提示「可前往充电桩自取 或 联系店员」。

  • 订单信息：显示下单账号（微信号 / 手机号）；店员账号可见全部订单。
  • 品牌：logo 统一为平台品牌狗；头部副标题「龙岗AI · 机器狗即时配送」。
开发原则：① 小程序是平台配送能力的一个「轻客户端」：商铺 / 送达点 / 电话 / 订单状态全部平台同源，小程序不持数据；② 语音下单是第一交互（大按钮置顶），表单是语音的兜底与确认；③ 送达点依赖空间语义匹配，这是与竞品配送小程序的核心差异点，匹配失败要友好拒单；④ 所有异常状态（断网 / 滞留 / 超时）都要给用户一个可执行的下一步（自取 / 联系店员 / 重新配送），不留死胡同。
