二、详细方案与开发原则

1. 远程接管与遥控（监控中心）

远程接管本期改为「平台弹窗 + 狗原生控制台」的形态：平台不再自绘遥控界面，而是在监控中心里给每台具身开一个全屏接管窗口，窗口正文直接内嵌狗厂商的原生控制台页面。围绕这个窗口，入口、地址配置、任务联动和结束去向做了如下调整。

  • 入口：在监控中心 3D 视口选中一台具身后，右侧「具身信息」面板内新增「远程接管」按钮，仅管理员角色可见；普通操作员不显示该入口。
  • 弹窗形态：点击后弹出全屏弹窗，标题栏使用平台统一样式，文案为「远程接管 · {具身名称}」（替换掉原控制台自带的系统名称标记）；正文为 iframe，内嵌狗原生控制台（当前联调地址 http://123.57.179.149:8188/）。
  • 连接控制地址：控制台 URL 不是写死的，而是在接入中心「基础信息」里按具身配置（新建向导的「新建设备」步骤同步采集，新建 / 查看 / 编辑三个界面的字段保持一致）；未配置地址的具身，接管按钮置灰并提示先补录地址。
  • 加载失败处理：iframe 约 5 秒加载不出来时，界面上仅提示「控制台加载失败」——本期去掉了原来的「显示示意图」按钮和降级示意图，也不展示任何链路兜底类说明文字。
  • 接管联动：点击接管的瞬间自动暂停该具身当前任务，并在任务执行记录中写入「人工接管」节点，保证事后可追溯。
  • 结束接管：点击「结束接管」弹出确认框，按钮精简为两个去向——「恢复原任务」「回到充电桩 / 待命区」（原「顺延至下一排班」「保持待机」按钮去掉）；确认框右上角提供无白底的 ✕，点击 ✕ 等于取消本次结束操作、继续接管。
开发原则：① 平台不自绘遥控 UI，一期统一走狗原生控制台 iframe，控制台地址做成按具身可配置项；② 接管 / 结束接管都必须落执行记录，保证任务审计链完整；③ 结束接管的默认去向是「回到充电桩 / 待命区」，对应点位取自空间管理「充电/待命」用途点位。

2. 网络模式管理（监控中心 · 具身信息内）

复杂长程任务必须支持逐机切换在线 / 离线工作方式。本期在具身信息面板内新增网络模式切换，并围绕「离线后平台侧怎么看、数据怎么补、载货断网怎么处置」补齐了三个配套区块。

  • 模式切换：网络模式是逐具身属性，入口收在「具身信息」面板内，可切换 在线 / 离线；弱网按钮保留但置灰，点击提示「开发中」，本期不开放。
  • 离线具身的位置呈现：切到离线后，地图上该具身标记改为「最后已知位置 + 离线时长」，平台侧按最后上报坐标 + 时间戳判定，让操作员一眼知道狗最后失联在哪里、失联多久。
  • 离线任务包：新增离线任务包列表，显示任务名 / 点位数 / 是否完整接收，未完整接收的标「待补传」；媒体回传进度显示「已回传 x/y · 断点待续传」，恢复网络后自动续传，不丢不重。
  • 已取货断网处置：在离线任务包区块上方新增独立区块，用完整友好的提示文案说明当前处置策略——默认唯一策略「自动回充电桩等待重连」（已取货状态下不允许原地等待）+ 重连倒计时，并注明小程序订单已同步显示「配送异常-处理中」，让操作员清楚用户侧看到的是什么。
开发原则：① 网络模式是逐机属性，切换入口统一收在具身信息面板，不做全局开关；② 断网期间的一切数据（点云 / 图像 / 日志）按「断点续传」设计，有网即回传，不丢不重；③ 载货断网属于配送异常链路，平台侧处置与小程序订单状态必须同源同步。

3. 小舆交互优化（全局 AI 助手）

小舆从「一次性指令框」重构为「有上下文的对话式助手」。原有的交互是单轮问答、不留记录，本期按主流大模型对话产品的方式重做会话区，同时收敛入口、统一视觉。

  • 多轮对话 + 上下文记忆：会话以时间线形式留存、可上翻；支持上下文追问（先说「去 3F 巡检」，再说「改成 4F」即可修正）；新增历史会话列表，可切换 / 新建会话。
  • 快捷入口重构：去掉面板下方原来固定的几个快捷按钮，改为两处更轻的形态——新会话开场由小舆主动发欢迎语 +「可以这样说」示例气泡（示例按该具身的岗位能力集与绑定场景过滤）；输入框上方新增一行可横滑的快捷胶囊：下任务 / 空间状态 / 狗子状态 / 异常复核，点击即填入输入框，只引导不直达。
  • 「下任务」不再跳页：点击「下任务」胶囊后不再弹出新建任务弹窗，而是在对话区内给出 NL 引导文案（与新会话引导一致），引导用户直接用自然语言描述任务，走第 5 节的解析链路。
  • 面板形态：面板可拖拽移动、对话框可拖拽调整大小（左上角斜纹手柄，宽 300–640px / 高 340–86vh）、可吸附右边缘展开为侧栏；Pad 端同一页面响应式适配；去掉头像下方「小舆.xiaoyu」文字标签。
  • 视觉统一：对话区改为深底卡片 + 细滚动条；用户气泡 / 小舆气泡 / 任务卡片 / 解析卡片 / 告警卡片统一圆角、边框与状态色；语音交互有「拾音中 / 识别中 / 执行中」三态动画，识别文字实时回显在输入框。
  • 主动提醒：异常告警（待复核 / 任务失败 / 电量低 / 越界）以小舆新消息的形式进入会话，消息内附按钮直达对应处置页，沟通与处置留痕合一。
开发原则：① 小舆是「有上下文的对话式助手」，不是一次性指令框——所有交互留痕、可追问、可回溯；② 快捷入口只做「引导填词」，真正的任务下达走 NL 解析链路（见第 5 节），不做硬编码按钮跳页；③ 告警进会话 = 通知中心 + 处置入口二合一。

4. 空间数据采集任务（任务中心）

任务中心新增业务类型「空间数据采集」，用于「狗去扫某几层的点云」这类纯采集任务。设计上刻意做减法：扫图过程由人遥控完成，平台只负责圈定范围、下发任务、回收数据。

  • 新建只需选范围：新建采集任务只需选择 单体 + 楼层，支持一次选多层；不支持跨建筑——选中第二栋楼时前端拦截并提示。原方案里的扫描方式、点云密度、完成后动作等参数设置全部去掉。
  • 仅人工触发：任务类型锁定为「人为触发」，不提供周期 / 定时选项——扫图任务只能由人当面发起。
  • 执行即接管：保存下发后，狗启动前往目标楼层，平台界面自动跳转「远程接管」弹窗，由人控制狗完成扫图；过程中狗语音播报「开始扫描 XF / XF 扫描完成」，操作员与现场人员都能感知扫描状态。
  • 点云回传归属：扫描完成的点云文件按任务执行楼层归档（多层任务每层一个文件），文件附带信息记录（所属单体-楼层 / 采集时间 / 文件大小 / 采集任务名 / 采集人），在空间信息面板与媒体归档中可查。
  • 状态标记：回传文件带「已对齐落图 / 待比对」状态；与既有空间模型的比对本期不做，只保留「待比对」标记占位。
开发原则：① 扫图是「人控任务」：平台负责任务下发、跳转移交、数据回收，扫描过程本身交给远程接管；② 点云文件必须以「单体-楼层」为第一归属键，支撑后续按层比对与落图；③ 跨建筑拦截在前端与调度层双校验。

5. NL 任务自动解析（任务中心 + 小舆）

所有任务（无论是小舆里一句话发起的，还是任务设置页手动建的）都统一增加一步「AI 任务识别」：先解析空间目的地语义，再做路径规划，确认后下发。本期重点是把这条链路做完整、把路径规划弹窗改成「路径子模型」形态。

  • 先推理、再补填：AI 先自行推理完整任务要素（去哪、做什么、采什么、怎么回）；推理不出的缺项，以解析卡内高亮补填为主、小舆对话追问为辅，不阻塞对话。
  • 解析确认卡：新增解析确认卡，列出任务类型 / 目标位置（可点开空间地图改选）/ 点位要求 / 返回结果要求 / 路径规则，底部两个动作：「确认并规划路径」「重新描述」。
  • 路径规划弹窗改为路径子模型：不再加载全量模型，只显示空间（房间盒）+ 重点系统 / 设备 + 重点位置的轻量化子模型。弹窗打开后先显示「路径子模型规划及提取中」的小动画（约 3 秒），随后子模型图与推荐路径一起出现——推荐路径以加粗高亮线逐笔画出，图上与方案区只呈现这一条推荐路径，不再列多条备选。
  • NL 生成固定任务：识别出周期 / 时间字段（如「每天上午巡一遍」）时，确认后直接创建固定任务。
  • 无分期标识：语音下达的一次性任务仅在小舆会话内跟踪；界面上不出现任何「临时任务不进入列表」之类的分期提示，不对用户暴露开发节奏。
  • 入口统一：小舆输入框与任务设置页「🎙 语音/文字建任务」按钮共用同一个解析卡组件。
开发原则：① 解析链路 = 语义解析 → 岗位 / 能力校验 → 模板命中 → 确认卡 → 路径规划 → 下发，任何一步缺要素都在卡片内闭环，不阻塞对话；② 路径预计算只用子模型，是性能与「空间语义理解」展示的双重要求；③ 解析卡是公共组件，小舆与任务中心两处复用。

6. 接入向导扩展：充电桩 / 待命区 / 电量策略（接入中心）

新设备接入向导在原有「新建设备 → 现场连接 → 模组测试」的基础上，新增「充电与待命」环节，并把远程接管所需的控制台地址前移到新建步骤采集。同时设备角色做了精简。

  • 新增「充电与待命」环节：依次选择充电桩位置、待命区域（均引用空间管理中用途为「充电/待命」的点位，下拉选择），并设置电量双阈值——回充阈值（默认 20%）、禁派阈值（默认 35%）。
  • 充电桩连接测试：向导与基础信息编辑界面均新增「测试连接」按钮；未测通时拦截保存 / 注册，但允许跳过（稍后在基础信息里再配）；查看态显示「已对接 ✓」徽标。
  • 基础信息同步：充电与待命配置在基础信息页可查看、可编辑，与向导数据一致。
  • 新增「连接控制地址」输入框：「新建设备」步骤的连接参数下方新增该输入（远程接管控制台 URL，示例 http://123.57.179.149:8188/），值随注册写入设备档案，基础信息可补录 / 修改；未配置时监控中心「远程接管」按钮置灰。
  • 设备角色精简：角色下拉改为 通用机器人 / 巡检机器人 / 导览机器人 / 配送机器人 四项，去掉与之重复的原「岗位设定」字段；新建成功后页面默认跳到刚新建设备的基础信息。
  • 充电桩状态呈现：监控中心地图新增充电桩标记三态——空闲 / 占用（显示占用具身名）/ 故障。
  • 低电联动：电量条上加双刻度线；低于禁派阈值的具身标黄「暂停派单」；任务下发时电量不足直接拦截并提示。
开发原则：① 充电桩 / 待命区是「点位」，统一引用空间管理点位库（用途 = 充电/待命），不另建坐标体系；② 连接测试是保存前置校验但允许跳过，兼顾联调期与演示期；③ 电量策略（回充 / 禁派）作用于调度层，所有派单入口统一过电量闸门。

7. 本体与模组接入（接入中心）

能力模组页签按确定的硬件清单写死，模组状态管理从简单标记升级为「四态 + 可处置」，并让模组状态反向约束任务可调度性。

  • 模组清单写死 6 项：MID360 激光雷达 / 5G 数据模块 / 控制手簿电脑 / 扬声器拾音器模组 / 全景相机模块 / 空间智能模组。平台按这份清单写死对应的功能页面，新模组上线即平台发版。
  • 模组状态改为四态：已连接 / 异常 / 未连接 / 未搭载，界面中分别选一个模组示意一种状态；异常模组新增「重试连接」按钮与「连接日志」弹窗（展示最近 10 条连接事件）；新增「一键重连全部」按钮，点击后所有异常 / 未连接模组恢复为已连接（未搭载不参与）。
  • 状态反向约束能力：模组异常时，对应可执行任务开关反向置灰并注明原因；5G 数据模块异常时整机按离线处理。
  • 本体信息补齐：新增固件版本 / SDK 版本 / 最近心跳时间三个字段。
开发原则：① 模组状态是任务可调度的前置条件，状态 → 能力的映射在调度层统一判定；② 四态必须互斥且可解释（每个状态都有下一步动作：重试 / 查看日志 / 无）；③ 模组清单是硬编码白名单，新模组上线 = 平台发版。

8. 导航：点云地图与配准（接入中心）

接入中心具身详情里原来的「配准」页签升级为「导航」页签（位置在能力模组之后）。升级后它不再只是一次性的配准动作，而是这台狗全部点云地图的管理台：导入、搜索排序、启停、跨图通行、配准与合模查看都收在这里。

  • 点云地图列表：默认展示设备接入时导入的点云地图，每行含名称 / 空间 / 大小 / 上传时间 / 配准状态。新增「⬆ 导入点云」按钮，支持批量上传（.ply/.pcd/.las/.zip，导入后为待分配状态、待选 BIM）；支持按名称 / 空间搜索；搜索框右侧的排序改为平铺按钮组——按状态 / 按时间 / 按空间（按状态 = 已配准在前，按时间 = 上传时间倒序，按空间 = 单体序 + 楼层地下到地上），去掉了原来下拉加括号解释的形式。每张图可启用 / 禁用（禁用后调度不再使用该图）、导出、删除（二次确认）。
  • 跨图通行（按图配置）：从原来「整机一个跨图方式」改为每张点云地图单独配置跨层切图方式——楼梯 / 楼梯+电梯 / 电梯三种；选到电梯时需指定具体哪一部电梯（候选来自智能通行控制的梯控配置），并显示梯控连接状态徽标 + 「测试连接」按钮。
  • 配准：每张图选定对应的 BIM 模型（.ifc / .glb）后点「配准」进入手动配准（选点 / 移动配准：游标微调 + 人工输入坐标 + 比例调整）；自动配准按钮保留但灰显，点击提示「开发中」。配准完成后回写该图「配准」状态，结果保留、可随时重新配准。
  • 查看配准弹窗：列表工具区新增「🧩 查看配准」按钮，弹出「点云 · BIM 模型配准」弹窗。左侧是配准列表（点云 ↔ BIM 逐对）+ 未配对区（未选 BIM 的点云、无点云的 IFC 模型），徽标统一为配准 / 未配准两种，不再区分配对与配准状态；右侧为单一合模视口——默认显示整个单体「多层 BIM + 全部点云」的叠加效果（顶部可切换单体，未配准的楼层如 B1 在图上标注），点击左侧任一对则切换为该文件的 1v1 合模视图（含 RMSE / 重叠率，可返回整体视图）。
开发原则：① 点云地图以「单体-楼层」为第一归属键，与空间数据采集任务的回传归档口径一致；② 配准是「按坐标执行任务」的前置闸门，状态在列表与合模视图双端可见；③ 跨图通行是地图级属性而非整机属性——同一台狗不同楼层图可分别走楼梯或电梯；④ 合模视口默认给整单体视角（一眼看全楼），1v1 用于排查单层。

9. 门控对接（空间管理 · 智能通行控制）

门控 / 梯控配置从接入中心移到空间管理，新增「智能通行控制」页签（位于点位管理之后）。门和电梯在这里被当作「空间构件」对待：由空间语义自动识别、在模型上标注、在统一页签里配置。

  • 页面布局：左侧空间地图（顶部单体 + 楼层双下拉联动，门 / 梯标记可点选），右侧设置列表，左右约 5:7。
  • 门 / 电梯自动识别：空间管理的语义识别会把 BIM 中的门、电梯构件单独提取出来；空间组织模型区顶部新增「门 / 电梯」过滤开关，点亮即单独高亮这两类构件；点击标记弹出构件信息面板，通用构件能力（构件标签 / 列为关联设备）在门、梯构件上同样保留。
  • 门类型二元：自动门（配门控 API）/ 非自动门（视觉识别）；门状态：常开 / 常关。自动门未配 API 时红色显示，模型标记与门点列表同步标红，把配置缺陷显性暴露出来。
  • 统一网关 + 单门覆盖：配置第一扇自动门时可勾选「统一网关」，勾选后所有自动门默认共用视为配好，同时每扇门仍可单独改 API——兼容「整楼统一网关」与「商铺各自网关」两种现场形态；勾选框为可直接开关的普通开关（去掉原「暂不可改」的灰显处理）。
  • API 单源配置：空间组织构件信息面板中的门控 API / 梯控 API 只读（灰化禁编辑），门下注明当前生效来源（继承统一网关 GW-01 / 未配置 ⚠）；配置与修改入口统一收在「智能通行控制」。
  • 通行状态机：接近门 → 停下检测（视觉识别开 / 关）→ 开门请求 → 等待确认 → 通过。界面上的分支说明文字精简为「已开 → 直接通过；未开 → 发开门请求；超时（默认 20s）→ 重试 ×2」，去掉「分支：」前缀；超时再失败后的人工兜底（小舆推送 / 远程开门 / 改路线 / 终止）属于内部设计口径，不在界面展示。
  • 门控页签内容：门点管理表（名称 / 所在空间 / 类型 / API / 通行策略 / 关联路线）+ 通行日志。
  • 监控中心联动：地图门标记区分自动 / 非自动，通行中闪烁。
开发原则：① 门 / 梯是「空间构件」不是独立设备台账，识别、标注、配置都挂在空间模型上；② 门控 API 配置遵循「默认统一网关、单门可覆盖」的最小配置原则；③ 未配 API 的自动门是配置缺陷，必须在地图与列表双端红色显性暴露；④ 门 / 梯 API 单源维护——只在「智能通行控制」配置，空间组织侧只读，防止双写不一致。

10. 梯控对接（空间管理 · 智能通行控制）

梯控与门控同页签管理。乘梯动作定为一条 9 步串行指令链，每步有成功判定与超时重试；界面只呈现配置项与状态，降级与异常分支说明不下界面。

乘梯指令集（定稿顺序）：

呼梯 → 到梯检测 → 进轿厢（不改位姿）→ 选层 → 切图目标层 → 轿厢内重定位（平台自动指定点位）→ 到达判定 → 开电梯门 → 出轿厢
  • 电梯状态二元：可乘（已接梯控）/ 不可乘（未接梯控，红标）；电梯通过空间名称「电梯 / 电梯间」语义识别，无需人工标台账。
  • 电梯构件信息面板：梯控状态 / 服务单体（只读 = 当前所在单体）/ 服务楼层改为点击胶囊多选（去掉勾选框样式，点中即选中，保存为「B1、1F、3F」格式）/ 梯控 API / 轿厢定位方式。
  • 梯控配置表：电梯名称 / 服务楼层 / 梯控 API / 轿厢内定位方式；每个动作配下发指令、成功判定、超时重试。
  • 选层按支持 API 设计：电梯不支持选层 API 时由人工 / 机械按层，平台仅下发呼梯与到层检测——此为内部设计口径，界面不展示降级说明。
  • 异常分支：呼梯无响应（重试 → 人工）、轿厢内断网（到站自动恢复定位）；跨层任务在任务详情与地图上显示「乘梯中」节点——同为内部设计口径，界面不展示。
开发原则：① 指令链串行、每步有成功判定与超时重试，联调期可逐步排查；②「进轿厢不改位姿」是有意砍掉正对门位姿检测的简化决策，不要加回；③ 选层是必须保留的 API 能力项，降级只降「按层方式」，不降指令链结构。

  • P3 我的订单：时间倒序 + 状态标签 + 筛选；滞留订单在列表中正常显示「滞留提醒」状态（补上原列表缺状态的问题）。
  • P4 订单详情：全过程时间线；滞留判断——狗长时间未移动，或长时间未送达且未在执行其他订单 → 提示「可前往充电桩自取 或 联系店员」。
  • 订单状态机与按钮权限：排队中（可取消、不可重新配送）/ 配送中、已送达（仅联系店员，不显示取消与重新配送）/ 配送异常-处理中、滞留提醒（联系店员 + 重新配送）/ 已取消（只读）；取消与重新配送均二次确认。
  • 订单信息：详情首行显示「购买渠道 · 订单号」，进度页头部带渠道；显示下单账号（微信号 / 手机号）；店员账号可见全部订单。
  • 品牌：logo 统一为平台品牌狗（正脸头像，与平台左上角 / 登录页同源）；头部副标题改为「龙岗AI · 机器狗即时配送」。
开发原则：① 小程序是平台配送能力的一个「轻客户端」：商铺 / 送达点 / 电话 / 订单状态全部平台同源，小程序不持数据；② 语音下单是第一交互（大按钮置顶），表单是语音的兜底与确认；③ 送达点依赖空间语义匹配（含模糊匹配与别名库，语音与手动输入同一链路），这是与竞品配送小程序的核心差异点，匹配失败要友好拒单；④ 所有异常状态（断网 / 滞留 / 超时）都要给用户一个可执行的下一步（自取 / 联系店员 / 重新配送），不留死胡同。
